# دليل الاختبار — خطوة بخطوة

> مبدأ ثابت: **قراءة فقط أثناء كل الاختبارات**. لا إجراء كتابة على WebHIS،
> والطباعة تُترك لقرار الموظف (ز الطباعة) إلا إذا فُعّل الخيار بعد اعتماد التدفق.

## 0. اختبار السيرفر (منجَز مبدئياً — أعد عند أي نشر)

- [ ] `curl -u "<ext>:<secret>" http://maxcall.local:3001/api/his/patient/5080625`
      → `ok:true` و`card_no = 0EEDF9B48F2C63E3`
- [ ] نفس الطلب بدون auth → HTTP 401، وبكلمة مرور خاطئة → 401
- [ ] رقم غير صالح `abc` → `bad_pat_id`، ورقم غير موجود `999999999` → `not_found`
- [ ] الخدمة نشطة: `systemctl is-active maxcall-dashboard`

## 1. تثبيت الإضافة

- [ ] `chrome://extensions` → Developer mode → Load unpacked → مجلد `Extension/`
- [ ] أيقونة الإضافة تظهر بدون أخطاء (لا مثلث تحذير في البطاقة)
- [ ] الإعدادات: عنوان السيرفر + بيانات جهاز MaxCall + بيانات NextCare → "اختبار الاتصال" → سليم ✓

## 2. كشف المريض من صفحة المشفى

- [ ] افتح `http://solverserver:81/#/home/hmis/op/PatientRegistration` وسجّل الدخول
- [ ] افتح مريض اختبار: **Patient ID 5080625** (بطاقة NextCare `0EEDF9B48F2C63E3`)
- [ ] انقر أيقونة الإضافة → يظهر اسم المريض ورقم البطاقة تلقائياً
- [ ] **إن لم يظهر:** أدخل `5080625` يدوياً في خانة البحث → يجب أن تظهر البطاقة
      - إن نجح اليدوي وفشل التلقائي → ضبط `his-reader.js` (انظر §5)
- [ ] جرب كذلك مريضاً بتأمين آخر للتحقق من عدم مطابقته لشركة غير مدعومة (تظهر chip تحذير)

## 3. التدفق الحي — NextCare (المختبر الأول)

- [ ] انقر **"طباعة مستند التأمين"** مع مريض 5080625
- [ ] لوحة الحالة العائمة تظهر داخل تبويب NextCare وتُظهر الخطوات
- [ ] لو كانت الجلسة منتهية: دخول صامت → انتقال للاستعلام (بدون تدخل)
- [ ] صفحة `EligibilityChecking2.aspx`: رقم العضوية `0EEDF9B48F2C63E3` معبأ تلقائياً
- [ ] **إن ظهر "لم أعثر على حقل رقم العضوية":** شغّل وضع الاستكشاف من الـpopup
      وحدّث `findMemberInput/findTypeSelect/findNextButton` في `nextcare.js` (docs/ADAPTERS.md)
- [ ] النوع: إن كان محدداً افتراضياً → متابعة تلقائية بعد 3 ثوانٍ (قابلة للإلغاء بإغلاق اللوحة)
- [ ] صفحة النتيجة → لوحة "المستند جاهز" + زر طباعة → اطبع **نسخة اختبار واحدة** أو أغلق
- [ ] أعد التدفق ثانية والجلسة حية — يجب أن يستغرق من النقرة حتى صفحة المستند < 20 ثانية
- [ ] أعد التدفق بعد انتهاء الجلسة (أو من متصفح آخر) — يجب أن يعيد الدخول صامتاً

## 4. وضع الاستكشاف (probe)

- [ ] افتح تبويب موقع التأمين في أي صفحة → popup → "وضع الاستكشاف لصفحة التأمين"
- [ ] تظهر لوحة يسرد فيها الحقول والأزرار (IDs + تسميات) وفي Console جدول كامل
- [ ] استخدم المخرجات لتحديث دوال `find...` في المحوّل المعني

## 5. السجل التشخيصي (لإرساله للمطور)

عند أي مشكلة:

1. افتح الـpopup → أعد المشكلة إن أمكن (بها تسجيل أدق) → اضغط **"📋 نسخ السجل"**
2. الصقه في ملف نصي وأرسله — يحتوي: الإصدار، الوقت، كل الخطوات والأخطاء، روابط الصفحات
3. **لا يحتوي كلمات مرور** — تُخفى آلياً (`sanitize` في `src/lib/log.js`)
4. السجل يبقى طوال فتح المتصفح (`chrome.storage.session`) ثم يُمسح عند إغلاقه

لتوسيع التسجيل مؤقتاً: Console الـservice worker (chrome://extensions → Inspect)
يظهر نفس الرسائل مباشرة.

## 6. كشف المريض من صفحة المشفى

القراءة تعتمد على مكونات مثبتة من الإنتاج (انظر `his-reader.js`):

| الحقل | المحدد الأساسي | البديل |
|---|---|---|
| رقم ملف التأمين | `#ngb-tab-7-panel … div.wd-27` | أي `.wd-27` داخل لوحات ngb يناسب شكل رقم البطاقة |
| اسم التأمين | input داخل `app-patient-details` (المسار الكامل في الملف) | أي input قيمته تحمل اسم تأمين معروف |
| رقم الملف | أنماط URL ثم حقول مُسمّاة | نص معروض `Patient ID: …` |

إن تغيّرت الصفحة: افتح Console داخل صفحة المشفى وافحص العناصر الجديدة، ثم حدّث
`CARD_SEL` / `PAYER_SEL` أعلى `src/content/his-reader.js`. معلومات جزئية (بطاقة +
اسم تأمين بلا رقم ملف) تكفي للتشغيل — تظهر بوسم "بيانات الصفحة".

## 8. حل المشاكل

| العرض | السبب المحتمل | الحل |
|---|---|---|
| "سيرفر MaxCare غير متاح" | السيرفر/الشبكة | `curl` من جهاز الاستقبال، تأكد من `maxcall.local:3001` |
| "بيانات الاتصال غير صحيحة" | بيانات جهاز MaxCall | أعد إدخالها في الإعدادات (نفس ما يعمل به MaxCall) |
| "افتح صفحة المشفى أولاً" | لا تبويب مشفى مفتوح | افتح صفحة المشفى (أي صفحة) وأعد فتح الـpopup |
| المريض لا يُكتشف تلقائياً | صفحة Angular مختلفة البنية | إدخال يدوي + تحديث `his-reader.js` (§5) |
| اللوحة تظهر ثم "لم أعثر على حقل" | selectors صفحة الاستعلام | probe → تحديث `find...` في المحوّل |
| "فشل الدخول: ..." (NextCare) | بيانات/429/تغيّر بوابة | تحقق من الإعدادات؛ رسالة 429 = انتظر قليلاً |
| لا شيء يحدث بعد النقرة | سكربت المحتوى لم يُحقن | أعد تحميل تبويب الموقع مرة واحدة؛ إن تكرر → راجع console الـservice worker |
